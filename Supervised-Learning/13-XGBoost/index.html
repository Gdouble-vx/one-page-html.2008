XGBoost

Extreme Gradient Boosting — ฝึกต้นไม้ทีละต้นซ้ำ ๆ โดยต้นใหม่แต่ละต้นเรียนรู้จาก ความผิดพลาด (residuals) ของต้นก่อนหน้า จนกลายเป็นโมเดลที่ชนะการแข่งขัน Kaggle มากมาย

🎯 ลองเล่น

กด "เพิ่มต้นไม้" ทีละต้นเพื่อดู Boosting ทำงาน — ต้นไม้ต้นใหม่แก้จุดที่ต้นก่อนหน้าทำผิด ดู loss ลดลงในกราฟขวา

🧠 ทำงานอย่างไร

Fₜ(x) = Fₜ₋₁(x) + η · treeₜ(x)   โดย treeₜ เรียนรู้จาก residual ของรอบก่อนหน้า
  1. เริ่มจากคำทำนายพื้นฐาน (เช่น ค่าเฉลี่ย/ความน่าจะเป็น 0.5)
  2. คำนวณ residual = ค่าจริง − ค่าที่ทำนาย (จุดที่โมเดลยังผิดอยู่)
  3. ฝึกต้นไม้ต้นใหม่ให้ "เดา residual" ของต้นก่อนหน้าให้ถูก
  4. เพิ่มต้นไม้นี้เข้ากับโมเดลด้วยสัดส่วนเล็กน้อย learning rate (η) เพื่อไม่ให้ก้าวใหญ่เกินไป
  5. ทำซ้ำหลายร้อยรอบ — ทีละเล็กทีละน้อยโมเดลก็แม่นขึ้นเรื่อย ๆ

ทำไมถึงเก่ง: XGBoost เพิ่มเทคนิคหลายอย่าง — second-order gradient, regularization, ข้าม missing value, parallel training, pruning อัตโนมัติ — ทำให้เร็วและแม่นกว่า Gradient Boosting ทั่วไป

✅ ข้อดี

  • แม่นยำที่สุดในบรรดาโมเดลตารางข้อมูล (tabular)
  • เร็วมากด้วย parallel + cache optimization
  • มี regularization ในตัว → ลด overfit
  • จัดการ missing value ได้เอง

⚠️ ข้อจำกัด

  • ต้องปรับ hyperparameter หลายตัว (n_estimators, max_depth, eta...)
  • ฝึกช้าเมื่อข้อมูลมหาศาลและรอบเยอะ
  • ไม่เหมาะกับข้อมูล unstructured (ภาพ/ข้อความ) เท่า deep learning

⚙️ Parameter Tuning

XGBoost มีพารามิเตอร์เยอะ — จับคู่หลักคือ (learning_rate ↔ n_estimators) กับ (max_depth ↔ min_child_weight)

💡 eta เล็ก → ต้องใช้ต้นไม้เยอะขึ้นแต่แม่นกว่า · เลื่อน n_estimators เพื่อสร้าง/ลดต้นไม้แล้วดู loss

n_estimators (จำนวนต้น)
ค่าแนะนำ: 100 – 1000 + early stopping
จำนวนรอบ boosting ทั้งหมด
💡 ใช้ early_stopping_rounds=10 ดู validation — หยุดเมื่อไม่ดีขึ้น
learning_rate (eta)
ค่าแนะนำ: 0.01 – 0.3
สัดส่วนที่ต้นไม้แต่ละต้นมีส่วนร่วม — เล็ก = แม่นแต่ต้องต้นเยอะ
💡 ลด eta ลงครึ่งหนึ่ง → มักต้องเพิ่ม n_estimators ประมาณ 2 เท่า
max_depth
ค่าแนะนำ: 3 – 10
ความลึกของต้นไม้แต่ละต้น
💡 ข้อมูล tabular ทั่วไป depth 4 – 6 ก็พอ — ลึกเกิน = overfit
subsample
ค่าแนะนำ: 0.5 – 1.0
สัดส่วนข้อมูลที่สุ่มใช้ต่อรอบ (เหมือน bagging)
💡 0.8 ช่วยลด overfit และเร็วขึ้น
colsample_bytree
ค่าแนะนำ: 0.5 – 1.0
สัดส่วน feature ที่สุ่มใช้ต่อต้น
💡 ลดลง = ต้นไม้ต่างกันมากขึ้น (ดีเมื่อ feature เยอะ)
min_child_weight / gamma / λ
เริ่ม 1 / 0 / 1
regularization — กันโหนดที่จำข้อมูลจุดเดียว
💡 เพิ่มค่าเหล่านี้เมื่อ overfit — ช่วยให้โมเดลเรียบขึ้น

  • ทำนายการคลิกโฆษณา (CTR prediction)
